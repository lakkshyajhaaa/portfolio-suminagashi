## Overview

The Centre of Excellence in Food Safety (COE-FS) conducts critical academic research involving extensive laboratory datasets, sensor logs, and sample testing histories. Historically, data management across departments relied on disparate spreadsheets and manual data exports, complicating cross-lab collaboration and decelerating scientific publication workflows.

As a Software Engineering Intern, I collaborated directly with research stakeholders to architect and deliver a unified frontend research portal and containerized deployment infrastructure tailored for academic workflows.

---

## 01. The Problem

Research teams within academic labs face unique data challenges:

1. **Large Asynchronous Payloads:** Chemical and biological sample logs generate extensive tabular data that overwhelm unoptimized client interfaces, leading to browser freezing.
2. **Ambiguous Scientific Requirements:** Unlike commercial software with established user flows, researchers often have evolving investigative requirements that need rapid frontend iteration.
3. **Deployment Fragility:** Lab servers frequently lack modern continuous integration workflows, requiring self-contained, reproducible container configurations that run reliably without complex server dependencies.

### Who Experiences This Problem?
100+ active university faculty researchers, PhD scholars, and student investigators analyzing food safety sample data across laboratory cohorts.

## 04. Engineering Challenges & Trade-offs

### Challenge 1: Large Sample Datasets Degrading UI Responsiveness
- **Constraint:** Querying longitudinal sample records returned thousands of nested rows. Rendering these directly into standard HTML tables caused severe DOM layout thrashing and dropped frames.
- **Alternative Considered:** Requiring the backend to implement full server-side cursor pagination. However, backend changes were constrained by academic research timelines.
- **Selected Approach:** Implemented virtualized list rendering and client-side windowing alongside debounced input filters. By rendering only visible DOM elements within the viewport, scroll performance remained silky smooth at 60fps regardless of dataset magnitude.

### Challenge 2: Self-Contained Laboratory Server Deployment
- **Constraint:** The deployment target was an on-premise university server with varied dependency versions and strict firewall rules.
- **Resolution:** Authored an optimized multi-stage Dockerfile that builds the React application in a lightweight Node environment and copies production static assets into a minimal alpine-based Nginx container. This reduced image size by over 80% and guaranteed zero dependency conflicts on the host machine.
